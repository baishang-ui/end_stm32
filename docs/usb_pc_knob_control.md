# USB 旋钮控制电脑音量/亮度分析

## 1. 当前硬件条件

- 主控: `STM32F407VET6`
- USB: `USB OTG FS`，数据脚为 `PA11/PA12`
- 旋钮编码器: `PB12/PB13`
- 旋钮按键: `PB14`
- 显示: SPI OLED，可做本地状态反馈
- 软件栈: `RT-Thread` + `STM32 USB Device Library`

这套硬件具备把开发板做成 USB 人机接口设备的基础条件。旋钮负责输入，USB 负责把输入事件发给电脑，OLED 可以显示当前调节项和状态。

## 2. 这个功能是否可行

### 音量控制

可行性高。

原因是电脑系统普遍支持 HID Consumer Control。固件只要通过 USB HID 上报下面这两个 usage，系统通常就会直接响应：

- `0x00E9`: Volume Increment
- `0x00EA`: Volume Decrement

这条链路不需要专门驱动，枚举成功后一般即可使用。

### 亮度控制

可行，但要分场景看。

当前固件使用的是 HID Consumer Page 里的亮度 usage：

- `0x006F`: Brightness Increment
- `0x0070`: Brightness Decrement

这在以下场景里通常更容易生效：

- 笔记本自带屏幕
- 操作系统本身愿意把 HID 亮度事件映射到内部显示亮度

这在以下场景里不一定生效：

- 台式机外接显示器
- 通过 HDMI/DP 连接的普通显示器
- 某些桌面系统没有把 HID 亮度 usage 接到显示亮度控制链路

结论：

- “音量 + 亮度都走纯 HID” 这条路线可以先做，而且实现成本最低
- 但“亮度在所有电脑上都稳定可用” 不能只靠纯 HID 保证

## 3. 当前工程里的实现路线

当前工程已经适合走下面这条路线：

1. 旋钮由 `oled_hal_input.c` 读取增量
2. UI 中的 `PC` 页面维护两个目标值: `volume` 和 `brightness`
3. `device_service.c` 把目标值变化换算成一连串 HID 按键事件
4. `usb_d.c` 通过 USB `Custom HID` 把 Consumer Control usage 发给电脑

这样做的优点是：

- MCU 端逻辑简单
- 不依赖电脑端安装专用软件
- 音量控制可以很快落地
- 亮度控制可以先验证，再决定要不要补上位机

## 4. 这次改动后的交互方式

- 进入 OLED 的 `PC` 页面
- 选中 `VOLUME` 或 `BRIGHT`
- 按下旋钮进入编辑
- 旋转旋钮修改目标值
- 固件把变化量拆成 HID 增减事件发给电脑
- 长按旋钮返回

页面会显示 USB 状态：

- `USB: OFF` 表示 USB 栈还没起来
- `USB: ENUM` 表示 USB 已启动但电脑还没完成枚举
- `USB: SEND` 表示正在发送事件或队列还没清空
- `USB: READY` 表示当前可以继续发 HID 事件

## 5. 推荐的工程落地顺序

### 方案 A: 纯 HID，先快速可用

适合目标：

- 先做出“插上电脑就能控制音量”
- 在一部分机器上顺带验证亮度是否可用

实现内容：

- USB 设备枚举为 HID
- 音量发送 `0xE9/0xEA`
- 亮度发送 `0x6F/0x70`
- OLED 提供当前控制值和连接状态提示

优点：

- 无需上位机
- 结构简单
- 演示效果直接

缺点：

- 亮度兼容性依赖宿主机和显示设备

### 方案 B: USB + 上位机助手，追求亮度稳定

适合目标：

- 希望在 Windows 台式机或外接显示器场景下也稳定控制亮度

实现思路：

- MCU 继续通过 USB 和电脑通信
- 电脑端运行一个小助手程序
- MCU 把“旋钮加一格/减一格、当前模式是音量还是亮度”发送给助手
- 助手调用系统 API 或 DDC/CI 去调节亮度

推荐分工：

- 音量继续保留纯 HID
- 亮度改为“纯 HID 优先，失败时走上位机”

这样兼容性最好。

## 6. 关键风险点

- `STM32F407` 只有 `USB FS`，带宽足够做这个功能，但要保证 48MHz USB 时钟正确
- 旋钮抖动需要消抖，否则会连续误触发
- HID 是相对控制，不是直接把电脑音量设置成 37%，而是连续发送增减
- 亮度是否生效主要取决于电脑和显示器，不完全由 MCU 决定

## 7. 最终建议

对这块板子，最务实的路线是：

1. 先把 USB HID 音量控制做稳定
2. 同时保留 HID 亮度控制用于验证
3. 如果目标电脑是笔记本，大概率可以继续沿用 HID 亮度
4. 如果目标电脑是台式机或外接显示器，尽快补一个电脑端助手来接管亮度

这样风险最小，也最符合这套硬件的能力边界。
